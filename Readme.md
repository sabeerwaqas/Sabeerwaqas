## 📚 Engineering Philosophy

I try to approach software development from the perspective of **systems rather than just syntax**.

Instead of stopping at:

> "Does this code work?"

I try to ask:

* What happens with invalid input?
* What happens when two requests arrive simultaneously?
* What happens when the database is slow?
* What happens when a dependency fails?
* Is the data consistent?
* Can this query scale?
* Is this API easy to maintain?
* What happens under load?
* Is the implementation secure?
* Can another developer understand this six months later?

That's the direction I'm taking my engineering career: **from writing code that works toward building software that remains reliable when things don't go according to plan.**
